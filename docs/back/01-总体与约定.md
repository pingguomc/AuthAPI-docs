# 后端开发指导（一）——总体架构与通用约定

> 本文档面向各语言的后端开发人员（Rust / Java / Python / Go / Node.js 等），是**实现层面的共同约定**，语言无关、力求宽松。具体的 API 端点、请求/响应、错误码等一律以根目录 [`index.md`](../index.md) 及 `docs/` 下各端点文档为唯一准绳，本文档只描述这些文档之外、但实现共同点。

## 项目是什么

一个纯后端的用户认证服务，核心能力：

- 注册 / 登录：邮箱注册、密码/邮箱验证码登录、OIDC 登录/注册。
- 会话：登录后建立会话、登出、修改密码/角色/封禁时吊销会话。
- 账号资料：展示名、绑定、更改邮箱、更改密码、找回密码。
- 绑定关系：邮箱与各 OIDC 本质都是「绑定」，可解绑，但**任何时候至少保留一种登录方式**。
- 管理后台：用户列表/详情、封禁、强制下线、角色变更、审计日志。

## 分层的通用思想（不强求命名）

核心是**业务逻辑与技术细节解耦**：

- 业务核心（domain / application）：实体、规则、用例编排，不依赖数据库、缓存、邮件等具体实现。
- 适配层（adapter / infrastructure）：负责 HTTP 输入，以及数据库、缓存、邮件、OIDC、人机验证等外部能力的接入。
- 业务核心通过**接口（端口）**访问外部能力，由适配层实现并注入。

不同语言可以有自己的命名（模块、包、namespace、crate 等），不必强求目录布局一致，只要**依赖方向朝向业务核心**、业务不写死具体产品即可。

## 技术选型（仅供参考，自由搭配）

| 能力 | 建议 |
|:---:|------|
| 持久化 | 关系型库（SQLite 起步，生产可换 PostgreSQL/MySQL），见文件二 |
| 缓存 | 进程内或 Redis 即可（会话/验证码/锁定等时效数据），见文件三 |
| 密码摘要 | BCrypt |
| OIDC | 任选语言生态里成熟可靠的 OIDC/JWT 库 |
| 人机验证 | Turnstile / hCaptcha / reCAPTCHA / 极验 任选，见文件四 |

## 配置约定

分两类，职责不同：

- **底层配置**：HTTP 监听器、数据库、SMTP、API 端点前缀（默认 `/api`）等，不常热改。
- **业务配置**：OIDC 提供商列表、用户登录失效时效、验证码格式、邮件模板等，**应能热重载**，改配置不重启。

两者都应在首次启动时自动生成默认配置并提供注释说明。

## 通用技术约定

- RESTful API；`Content-Type: application/json; charset=utf-8`；编码统一 UTF-8。
- 时间对外统一 ISO 8601 UTC 字符串；内部用各语言对应的高精度时间类型。
- 密码用 BCrypt 摘要存储。
- 统一的机器可读错误响应结构（见 `index.md`）。
