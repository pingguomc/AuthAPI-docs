# 后端开发指导（五）——管理后台与审计

> 管理端点全部要求当前会话用户 `role == admin`（否则 403 Forbidden）。语言无关，听凭各团队实现，这里只讲业务要点。

## 角色 / 状态

- **role**：`user` / `moderator` / `admin`。
- **status**：`active` / `banned`；`banned_until` 可空，`null` 永久封禁。
- status 是**投影**，不直接写；封禁记录是事实来源（详见文件二）。

## 封禁（ban）

- 同一用户同时只有一条生效中的封禁记录；改时长「先删旧、再建新」。
- 创建：同步把 user 写为 `banned` + `banned_until`，并清该用户全部会话（该次清除不额外记 `session_revoke`）。
- 解封 = **物理删除**封禁记录：同步把 user 改回 `active`、`banned_until` 置空；写入审计；不清会话。
- 临时封禁到期走惰性回写（见文件二），列表靠查询条件保证正确。

## 强制吊销 / 角色变更

- 强制下线：清该用户全部会话，返回被清数量；显式发起的清除记 `user.session_revoke`。
- 角色变更：成功后清用户全部会话，保证降权即时生效；不额外记 `session_revoke`。
- 当前**不限制**修改自身或其他管理员角色，注意「唯一管理员降级后无人进后台」的锁死风险，只能手动改库恢复。

## 审计日志（只读）

只提供查询，不提供增删改。

- `action` 取值（`资源.动作` 风格）：`user.ban`、`user.ban_delete`、`user.session_revoke`、`user.role_change`。
- 写入规则：
  1. **先写审计、后做业务**，审计写失败则整体失败。
  2. `result` 只 `success` / `denied` 两个终态，不回填。
  3. 只记**鉴权层面**的拒绝（权限不足、角色不符）；普通 400/404 不记。
  4. 记录操作者 IP。
- 查询支持按操作者、目标用户、action（前缀匹配）、结果、时间范围、分页过滤。

## 查询要点（数据模型见文件二）

- 用户列表：支持分页，邮箱精确 / 用户名前缀匹配，按角色/状态筛选，注册时间范围，按 `created_at`/`last_login_at` 排序。
- 列表不返回 IP 与 OIDC 绑定信息（详情才有），列表不触发惰性回写；详情会。
- 详情返回最后一次登录 IP、注册 IP、OIDC 绑定列表。
