# 后端开发指导（三）——安全、会话与缓存

> 语言无关。会话/验证码/锁定等时效数据放缓存，另附通用的缓存键前缀约定。

## 会话机制（Cookie HttpOnly）

- 会话 Cookie 名 `sid`，属性 `HttpOnly=true`、`Secure=true`、`SameSite=Lax`、`Path=/`，通过 `Set-Cookie` 下发。
- `HttpOnly` 前端 JS 读不到；`SameSite=Lax` 防大部分 CSRF；`Secure` 使 cookie 仅 HTTPS 下传输，**生产必须 HTTPS**。
- 会话 ID 用随机 UUID，**存缓存、不落库**。

## 会话吊销

以下任一操作都清除该用户**全部**会话：

- 修改密码；管理后台变更角色；创建封禁；强制下线。
- 其中只有「显式强制下线」在审计里记 `user.session_revoke`；作为副作用触发的清除不重复记。

## 密码安全

- BCrypt 摘要存储。
- 密码强度下限：**含字母和数字且不少于 6 位**；改密时新密码不得与旧密码相同。

## 登录防爆破

- 登录失败次数过多 → 临时锁定账号，锁定期满自动恢复。
- 用缓存记录失败计数与锁定截止时间；锁定期内拒绝该账号登录。

## 登录/会话与封禁的联动

- 封禁用户不允许建立新会话（登录被拒，语义 `UserBanned`）。
- 鉴权与登录路径参与临时封禁的**惰性回写**（见文件二）。

## 缓存键前缀约定（建议统一）

缓存只放时效数据：会话、邮箱验证码、锁定、限频。建议统一用小写前缀 + `:` 分隔，方便排查，具体前缀可按团队习惯调整：

| 用途 | 示例键 | 说明 |
|:---:|:---:|------|
| 会话 | `session:<sid>` | 会话 ID → 用户、过期时间等 |
| 按用户吊销会话 | `user:sessions:<userId>` | 该用户全部 sid，便于批量失效 |
| 邮箱验证码 | `email:code:<email>` | 验证码、过期时间、用途 |
| 邮箱发送限频 | `email:ratelimit:<email>` | 防轰炸 |
| 登录失败计数 | `login:fail:<email>` | 计数 + 窗口 |
| 登录锁定 | `login:lock:<email>` | 锁定截止时间 |
| OIDC 流程临时数据 | `oidc:state:<sid>` 等 | state / code_verifier / redirect_uri，用后即清 |

约定要点：

- **按用户吊销**需能按 user 维度删掉全部会话（如维护 `user:sessions:` 索引或用通配删除）。
- 各项 TTL 从业务配置读取，不硬编码（登录失效时效、验证码时效等）。
- 会话/验证码/锁定都在内存缓存，**进程重启即失效**，属预期，不视为数据丢失。

## 权限校验

- 普通用户端点：持有有效会话即可。
- `admin` 端点：在有效会话基础上校验会话用户 `role == admin`，否则 403 Forbidden。
