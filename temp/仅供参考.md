# CLAUDE.md

这是一份给 Claude Code (或其他 AI 编程助手) 的代码库指南。

## 项目概述

这是一个名为 `RedStarAuth` 的纯后端应用，采用领域驱动设计 + 六边形架构。核心是一个用户认证系统：支持邮箱注册、OIDC 登录/绑定、会话管理、密码与邮箱管理。

## 技术约定

* 每个包都设置 `package-info.java`，并编写 Javadoc 注释。
* 采用领域驱动设计 + 六边形架构：`domain`（纯领域，不依赖框架）、`application`（用例）、`adapter`（输入/输出适配器）、`shared`（跨层共享的配置与异常）。

### 安全

采用 Cookie HttpOnly 会话保证安全性。会话 Cookie 名为 `sid`，属性 `HttpOnly=true, Secure=true, SameSite=Lax, Path=/`，前端通过 `Set-Cookie` 获取。会话 ID 为随机 UUID，存储在 Caffeine 缓存中。

密码使用 BCrypt 加密存储。登录失败次数过多会暂时锁定账号（防暴力破解）。

### 配置文件

默认配置文件 `application.yaml` 不支持热重载，负责底层配置：HTTP 服务器、数据库、SMTP 邮件系统、API 端点前缀等。不负责业务逻辑。

* API 端点前缀可配置，默认为 `/api`，此配置位于 `application.yaml`（键 `api.prefix`），业务代码统一用 `${api.prefix}` 引用。

config 文件夹下设置这些配置文件，支持热重载：
* `OIDC.toml` 配置 OIDC 提供商列表，OIDC 提供商数量不做限制。
* `user.toml` 配置用户相关。包括启用的登录/注册方式、用户登录失效时间、用户密码加密方法等。
* `email.toml` 配置验证码生成格式，邮件主题/正文模板等。

全部配置文件均在本应用第一次启动时自动在 根目录(`application.yaml`) 和 config目录 生成，并且应当配有中文注释。生成逻辑见 `shared/config/ConfigInitializer.java`。

### 领域实体(将存储在持久数据库的内容)

* 表示时间的，使用 `Instant` 或 `Duration(主要是从配置文件读取时)`。
* 用户的 邮箱和OIDC 在本质上应当视为绑定，可解绑。但是任何时候都必须保留至少一个，也就是说解绑前需要检查有几个绑定方式。

#### 用户(表名 ：User)

`用户` 采取随机的 UUID 来作为主键。支持 `邮箱注册` 和 `OIDC注册`，支持 `密码登录` 和 `OIDC登录`。两种注册方式注册的用户都可以互相绑定其他注册方式。
支持解绑，但最少有一个可登录的方式。有邮箱的支持 `找回密码`。

字段列表如下：

|      名字      |   描述   | 备注                                    |
|:------------:|:------:|---------------------------------------|
|      id      |  用户ID  | 全局唯一，不可更改，数据库主键                       |
|    email     |  用户邮箱  | 若通过OIDC注册则可为NULL，不得为空字符串，可修改。但是UNIQUE |
| passwordHash | 密码哈希值  | 若通过OIDC注册则可为NULL，不得为空字符串，可修改          |
| displayName  | 用户展示名  | 可修改                                   |
|  createdAt   | 用户注册时间 | 不可修改                                  |
|     role     |  用户角色  | 可取-1,0,1,2 四种                         |

#### OIDC记录(表名 ：OidcRecord)

|     字段名      |                       描述                        |
|:------------:|:-----------------------------------------------:|
|     `id`     |                      主键标识                       |
|   `userId`   |                    关联的用户 ID                     |
| `providerId` | OIDC Provider 配置标识（如 `"google"`, `"microsoft"`） |
|   `issuer`   | OIDC Issuer（如 `"https://accounts.google.com"`）  |
|  `subject`   |        OIDC Subject（用户在该 Issuer 下的唯一标识）         |
|   `email`    |                 可选，从 OIDC 获取的邮箱                 |
|  `username`  |                可选，从 OIDC 获取的用户名                 |
| `createdAt`  |                      创建时间                       |
| `updatedAt`  |                      更新时间                       |

* 一个用户可绑定多个 OIDC Provider，同一 Provider 下只能绑定一个账号。
* 同一 (issuer, subject) 全局只能绑定到一个用户。
* 登录时若 (iss, sub) 已存在则直接登录，否则自动注册并建立绑定。
* 若使用 OIDC 注册的用户未设置密码，则必须至少保留一个 OIDC 绑定。

### 持久数据库

暂时使用 sqlite 作为持久数据库。领域实体应当存储于持久数据库中。建表脚本见 `resources/schema.sql`，仅包含 `User` 与 `OidcRecord` 两张表。

### 缓存系统

暂时使用 Caffeine 作为缓存系统。存储数据库中不存储的时效性较强数据。

用户登录会话采用缓存，邮箱验证码等具有时效性的均采用缓存。缓存实现位于 `adapter/outbound/cache/`，领域通过 `domain/user/service/` 下的端口接口访问。

### 邮件

以下操作需要发送并让用户填入邮箱验证码：
* 使用邮箱注册
* 找回密码（先检查是否有此邮箱）
* 修改密码（先检查是否绑定了邮箱）
* 更改绑定的邮箱（新邮箱需要接收验证码）

邮件发送通过 `adapter/outbound/email/SmtpEmailSender.java` 实现。若 `application.yaml` 中未配置 `spring.mail.host`，自动进入开发模式，将验证码打印到日志（标记 `[DEV-MAIL]`），便于本地测试。

### OIDC注册和登录

OIDC登录时若 (iss, sub) 不存在则自动注册。OIDC 采用 Authorization Code Flow + PKCE（S256），校验 `state`、`code_verifier`、`id_token` 的签名/iss/aud/exp。客户端实现见 `adapter/outbound/oidc/NimbusOidcClient.java`。

## API 设计

端点前缀为 `/api`（可配置）。所有端点与错误码的完整定义见 `API端点文件.md`，以该文件为准。

## 开发此项目

在开发此项目时需注意测试，API接口需要造数据测试并通过，保证可以部署到生产环境。全部进行完之后，要更新项目根目录下的 `项目状态文档.md` ，填写四个H2标题下的内容。

### 测试

* 集成测试（模拟生产环境）：`src/test/java/.../RedStarAuthApplicationTests.java`，使用内存 SQLite + 随机端口，覆盖注册、登录（密码/验证码）、me、改密、换邮箱、登出、OIDC 各端点。
* 单元测试：`domain/user/aggregate/UserTest.java`、`domain/user/vo/EmailTest.java`、`adapter/outbound/oidc/NimbusOidcClientTest.java`。

运行测试：`./gradlew test`。构建 jar：`./gradlew bootJar`。

### 生产环境部署提醒

* 配置 `config/OIDC.toml` 中的真实客户端 ID/密钥、JWKS 与 issuer 端点。
* 在 `application.yaml` 配置真实 SMTP 以发送邮件（否则验证码打印到日志）。
* 建议配置 HTTPS，因为会话 Cookie 标记了 `Secure`；HTTP 下 Cookie 不会发送。
* 会话与验证码存储在内存缓存中，重启后丢失（符合缓存系统约定）。
